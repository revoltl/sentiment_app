# 基于大语言模型的消费者评论情感分析系统 技术说明

本文说明各模块的实现方式、数据流与关键参数，供二次开发与复现参考。

---

## 1. 核心架构：分层与协作
项目采用 **“主干推理 (Primary) + 分支支持 (Branch)”** 的异步架构：
- **分层设计**：主流程 `src/pipeline_main.py` 仅负责核心调度与推理，所有预处理（LDA）、知识增强（RAG/WebSearch）、后处理（Parser）和科学评估（Eval）均作为独立分支运行。
- **数据中转**：各模块通过标准化的 CSV/JSON 文件进行通信，确保了流程的可回溯性与容错性。

---

## 2. 技术细节深度解析

### 知识增强一：检索示例与嵌入
- **向量化表征 (Embedding)**：利用 `OllamaEmbedder` `src/utils/rag_utils.py` 调用预训练模型，将文本转化为高维向量。支持异步并发请求以充分利用硬件（如 RTX 5090）性能。
- **本地向量库**：基于 `FAISS` 库构建 `src/utils/rag_utils.py`。
- **检索算法**：采用 **内积 (IndexFlatIP)** 索引，在执行前对查询向量与库中向量进行 **L2 归一化**。在这种状态下，内积等同于 **余弦相似度 (Cosine Similarity)**，实现语义层面的 Top-K 精确检索。
- **Few-shot 动态注入**：根据相似度得分（Score），自动筛选最相关的历史案例并格式化为示例字符串，动态注入 Prompt，提升模型在特定领域的判别精度。

### 知识增强二：联网词条释义
- **三阶段流程 (`web_utils.py`)**：
    1.  **关键词提取 (Extraction)**：使用轻量级 LLM (`EXTRACTION_MODEL`) 自动识别评论中的“网络热梗”、“疑似词”或“特定实体”。
    2.  **多源搜索 (Searching)**：通过 DeepSeek 官方接口或 Tavily 构建针对性查询（如：“{term} 是什么梗 网络用语意思”），获取多源实时网页内容。
    3.  **语义总结 (Explanation)**：使用核心 LLM (`EXPLANATION_MODEL`) 对搜索结果进行清洗与总结，输出包含“背景定义、涉及实体、情感倾向”的结构化 JSON。
- **上下文注入**：总结后的背景知识被注入到 10 段式 Prompt 的第 10 段，使模型能够理解极具时效性的社交媒体内容。

### 主题挖掘：LDA 与可视化
- **概率生成模型 (`topic_analysis.py`)**：采用 **LDA (Latent Dirichlet Allocation)** 算法，假设文档是主题的混合，主题是词的分布。通过变分推理（Variational Inference）迭代计算文档-主题分布。
- **数据预处理**：包含停用词合并过滤、结巴分词、TF-IDF 关键词提取，确保主题建模的纯净度。
- **可视化原理**：集成 `pyLDAvis`，基于 **Jensen-Shannon 散度** 计算主题间的空间距离，并将高维主题投影至 2D 平面，直观展示主题的流行度与区分度。

### 推理引擎：提示词的十段组装
- **结构化约束**：主流程将 Prompt 拆分为角色、主题背景、背景信息、评论内容、思维链引导、标签要求、输出示例、RAG 增强、关键词匹配、Web 搜索等 10 个逻辑段落。
- **思维链分离**：利用正则表达式匹配 `<think>` 标签 `src/pipeline_main.py`，把思维链与最终结论分开。

### 后处理：结果解析与标签对齐
- **JSON 提取 (`parser_utils.py`)**：按多层规则依次尝试，从模型原始响应中提取合法 JSON。
- **模糊标签对齐**：当模型输出非标准标签时，系统通过 **标签词表映射** 自动纠正为预设的合法标签。
- **稀疏矩阵展开**：针对 Aspect 任务 `src/result_parser.py`，解析器会将 JSON 列表展开为 18 个独立的“维度列”，为后续评估提供底层支持。

### 评估体系：三类任务的准则
- **分类任务 (Class)**：计算 Accuracy, Weighted-Precision/Recall/F1。
- **维度任务 (Aspect, `model_evaluation.py`)**：采用 **全局微平均 (Global Micro-average)**。将 18 个维度的预测结果视为一个整体进行比对，有效处理了评论数据中维度极其稀疏（大部分为“未提及”）的问题。
- **主题任务 (Topic)**：采用 **双元组匹配逻辑 (Tuple Match)**。只有当模型预测的“主题名称”与“情感极性”同时命中 Ground Truth 时，才判定为正确。

## 3. WebUI 交互技术亮点
- **流式日志**：基于 **Server-Sent Events** 技术，实现后端 Subprocess 输出到前端控制台的零延迟同步。
- **布局规则**：Dashboard 会根据媒体文件的类型与文件名特征，自动计算最优网格占比（如热力图、LDA 交互视图自动占 2 列）。
- **避免缓存**：图片加载动态注入随机时间戳，确保实时显示最新生成的分析图表。

---

## 4. 关键文件索引
- `src/pipeline_main.py`: 推理核心与 10 段式 Prompt 组装逻辑
- `src/utils/web_utils.py`: WebSearch 提取-搜索-总结管线实现
- `src/utils/rag_utils.py`: FAISS 向量库与余弦相似度检索实现
- `src/model_evaluation.py`: 多任务评估准则与混淆矩阵绘制
- `src/utils/parser_utils.py`: JSON 提取与标签对齐逻辑
